# Three-minute AstraFactory demo

Audience: someone who has never seen the app. Show one product and one evidence-backed improvement loop. Use the Bench arm project for the prepared example; label prepared work honestly.

| Time | Screen | What the audience should understand |
| --- | --- | --- |
| 0:00–0:20 | Home prompt | Describe a physical product. Astra assembles the engineering work around the goal. |
| 0:20–0:40 | Brief | Here is the product and what it must achieve. Open the short goal, not the entire agent assignment. |
| 0:40–1:15 | Design | Orbit the real generated assembly; switch to an exploded view. This is inspectable geometry, not a generated illustration. |
| 1:15–2:00 | Test | Show one measured finding and its affected part. Explain the consequence in plain language. Open supporting evidence only if needed. |
| 2:00–2:40 | Improve | Show the linked engineering correction and the independent re-test. If it fails or is pending, keep that outcome visible. |
| 2:40–3:00 | Overview | Return to the artifact and the result. The point is a traceable design/test/revision loop. |

Default workspace: four stages, one visual artifact, a short status, and the team. Detailed ID/ME/EE/manufacturing workstreams, full Markdown reports, transcripts, tool logs and handoff history live in Engineering view.

Do not open a session full of raw prompts as the first screen. Do not tour all the panels. Do not equate CAD motion with physics, a completed chat with a passing test, a sampled clearance check with a continuous proof, or a preliminary assembly with a production-ready arm. Robot policy learning is a separate capability and must have its own actual evidence before it is claimed.
