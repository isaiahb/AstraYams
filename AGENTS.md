## Own the critique and next-goal loop

The user explicitly wants the agent to infer subsequent engineering goals from
their demonstrated standards, rather than requiring the user to identify every
discrepancy and authorize every routine iteration. Treat the following as a
working interpretation of their project preferences, revisable by user steering:

- Physical causes and anatomical/engineering coherence matter: geometry, mass,
  connections, material response and contact must explain the visible behavior.
- Build something useful for real robot learning. Increase detail where it can
  change perception, manipulation, failure or transfer; avoid complexity without
  task-relevant benefit. Numerical stability alone is not physical accuracy.
- Inspect the whole result across views and over time, including transitions,
  neighboring objects and failure cases. Do not wait for the user to discover
  visible defects, hidden shortcuts or omitted components.
- Ground decisions in multiple appropriate references and discriminating tests.
  Separate observations, hypotheses, fitted parameters and unresolved unknowns.
- Show inspectable progress: actual before/after renders and motion, with useful
  cameras and orbitable replay. Review those artifacts yourself before reporting.
- Preserve accepted work, rejected trials and reusable parametric/experimental
  methods. Keep this manual research loop ahead of app/skill productization.

At each milestone, audit remaining mismatches, rank them by task consequence,
evidence and the effort needed to resolve uncertainty, then choose a concrete
next outcome and acceptance evidence. Continue authorized work on that outcome;
do not turn every local pass into a request for the user to plan the next step.
Use progress updates for steering and review. Ask when missing user knowledge,
conflicting priorities or a material scope/cost commitment actually requires it.
Do not invent real measurements, silently expand scope, or imply background
execution after the active turn ends. See docs/simulation/REALISM-METHOD.md and
the current work ledger for the detailed review loop and chosen milestone.

## Biological rule provenance

User requirement: every scripted biological behavior must be justified by researched biological findings. For plant generators, track each behavior separately from its numeric parameters. A general anatomy citation does not justify a node cutoff, fixed delay, growth rate, branch angle, organ lifespan or universal cultivar rule. Record exact source, relevant finding, study population, supported scope and transfer limitations. Unsupported behavior must be explicitly labeled a hypothesis and excluded from claims of biological realism; do not silently substitute an arbitrary rule. Numerical defaults remain uncalibrated unless source-linked measurements justify them. Computational limits must be labeled study limits, not biological termination. Preserve legacy versions and audit them before claiming compliance. Do not claim all rules are supported merely because the model has a sources list.
